## 一、这次改了什么

1. **采集插件升级 v1.7.0 → v1.7.1**，做成「邀请制」并接入本仓库账号体系（账号登录 · **1 码 2 用**：一个邀请码注册一个账号，账号同时通三阶引擎 + 采集插件）。
2. **新增后端端点 `src/app/api/auth/me/route.ts`**（给插件校验登录态）：
   - 优先读 `x-sanjie-session` 请求头（插件用 `chrome.cookies` 取 `sanjie_session` 值放进头，规避 SameSite 跨站不带 cookie），否则回退读 Cookie 头。
   - 用 `lib/auth.ts` 的 `parseSession` 验签；验签通过后再调 `isAccountActive(username)` 查 `prisma.user.status`，**被禁用/删除的账号即时 401**（不等 8h 会话过期）；DB 抖动时 fail-open（放行已验签会话，不误锁）。
   - `export const runtime = "nodejs"`（要跑 Prisma）；带宽松 CORS；中间件已放行 `/api/auth/*`，不会被未登录拦在 handler 前。
3. **`src/lib/accounts.ts` 新增 `isAccountActive(username)`**：按用户名查账号是否仍有效（未禁用/未删除），不校验密码。
4. **`src/lib/auth.ts`：`getHmacKey` 加生产 fail-fast** —— 仅「服务端 + 生产 + `SESSION_SECRET` 回落到公开默认值」时抛错。
   - ⚠️ **任何实例都必须设 `SESSION_SECRET`**（`openssl rand -hex 32`），否则会话可被伪造（同时击穿网站登录与插件门槛）。`.env.example` 已补占位说明。
5. **`src/app/tools/page.tsx` 升 v1.7.1** + 邀请制登录说明；`public/downloads/` 只留 `sycm-keyword-collector-v1.7.1.zip`（旧 v1.4.1 / v1.6.0 已删）。
   - ⚠️ `public/downloads/` 无鉴权对外，**别往里放任何含租户数据的文件**。
6. **导出 Excel 套三阶引擎青绿色系样式**（表头/关键列/命中高亮/斑马纹/冻结/筛选/处理说明卡片）；并修复「衍生采集手动中断后导不出已采词表」的 bug（导出闸门改为以真实落库数据为准，而非 job 计数器）。

## 二、插件鉴权怎么接（1 码 2 用）

- 用户在 shaozhuangai.com 用**邀请码注册账号**（现有 `/api/auth/register` + `consumeInviteCode`，邀请码注册时只消费一次）→ 账号建好。
- 插件打开时 `chrome.cookies.getAll` 读 `sanjie_session` → 调 `/api/auth/me` 验签 → 已登录解锁，未登录引导去 `/login`。**插件不碰密码。**
- ⚠️ 插件 `background.js` 里 `SITE` **写死 `https://shaozhuangai.com`**（即 3000 生产）。所以无论哪个实例分发插件，插件都**只认 shaozhuangai.com 的登录态**。若要让插件认别的域，需改插件 `SITE` 并重新打包。
- 已知取舍：客户端门槛是「劝退」非数据访问控制（技术用户可绕；真正数据源是用户自己的生意参谋登录态）。
